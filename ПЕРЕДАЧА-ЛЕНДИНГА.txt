КАЛЕНДАРЬ СПОРТИВНЫХ СОБЫТИЙ 2026–2027 — ПЕРЕДАЧА ЛЕНДИНГА
Документ для размещения на сайте. Дата: 03.10.2026

====================================================================
1. ЧТО ЭТО
====================================================================
Одностраничный лендинг «Календарь спортивных событий». Показывает
спортивные и киберспортивные события с сентября 2026 по декабрь 2027:
273 турнира, 19 видов спорта и киберспортивных дисциплин.

Как работает для пользователя:
- лента месяцев, открывается текущий месяц;
- карточки турниров месяца, по 12 с кнопкой «Показать ещё»;
- кнопка «Фильтры» — выбор видов спорта;
- клик по карточке ведёт в линию (ссылки уже проставлены).

Исходники: https://github.com/AnastasiyaMakarenko/mb-sports-calendar
Рабочая версия: https://mb-sports-calendar-production.up.railway.app

====================================================================
2. ЧТО ВНУТРИ
====================================================================
index.html        — страница
css/style.css     — стили
js/data.js        — ВСЕ ДАННЫЕ: события, даты, ссылки в линию
js/app.js         — логика (фильтры, месяцы, карточки)
img/              — баннеры (фрибет для десктопа и телефона, шапка)
favicon.*         — иконки вкладки
exports/          — выгрузки списков событий и лиг в CSV (рабочие файлы)

Размер всего сайта ~1,5 МБ, из них картинки ~330 КБ.

3. КАК ПОСТАВИТЬ НА САЙТ
====================================================================
Сборка НЕ нужна. Это чистые HTML, CSS и JS без фреймворков,
без Node.js, без базы данных. Нужен только веб-сервер, отдающий
статические файлы.

Вариант А. Отдельная страница на домене (рекомендуется)
  Положить содержимое папки в каталог вида /calendar/ и отдать
  nginx или Apache. Адрес будет, например:
  https://сайт.ru/calendar/

  Пример конфигурации nginx:
    location /calendar/ {
        alias /var/www/calendar/;
        index index.html;
        try_files $uri $uri/ /calendar/index.html;
    }

Вариант Б. Поддомен
  calendar.сайт.ru с корнем в папке проекта.

Вариант В. Оставить на Railway
  Сейчас сайт развёрнут там и обновляется автоматически при
  изменении в GitHub. Можно просто привязать свой домен.

Требования к серверу: любой статический хостинг, HTTPS.
PHP, Node.js, база данных НЕ требуются.

ВАЖНО ПРО КЭШ
  В index.html у стилей и скриптов стоит версия, например:
  css/style.css?v=2026-10-03
  Это защита от кэша. При каждом обновлении файлов версия меняется —
  иначе у посетителей останется старая копия. Настраивать кэш
  отдельно не нужно, достаточно не трогать эти параметры.

4. КАК ОБНОВЛЯЮТСЯ ДАННЫЕ
====================================================================
Все события лежат в одном файле js/data.js. Одно событие — одна
строка вида:

  { id:'rpl', t:'РПЛ 2026/27', s:'football', g:'Футбол. Россия',
    st:'2026-07-24', en:'2027-05-29', d:'24.07.2026 – 29.05.2027',
    p:'Россия', status:'✔', i:5, url:'https://melbet.ru/...' }

Обновление — это правка этого файла и публикация новой версии.
Формат полей описан комментарием в начале файла.

Что обновляется регулярно:
- новые турниры и даты, которых раньше не было;
- переносы и отмены;
- ссылки в линию, если меняется структура адресов;
- состав участников и инфоповоды.

5. ЧТО НУЖНО ОТ ВАШЕЙ СТОРОНЫ
====================================================================
Чтобы обновления доезжали до сайта без ручной пересылки файлов,
нужен один из двух вариантов:

  1) Сайт тянет из GitHub (быстрее всего)
     На сервере один раз делается git clone репозитория, дальше
     обновление — это git pull (можно по расписанию или по webhook
     из GitHub). Доступ к репозиторию выдаётся на аккаунт компании.

  2) Выгрузка архивом
     Мы присылаем архив с обновлённым js/data.js и index.html,
     вы заменяете файлы на сервере. Медленнее и требует участия
     человека каждый раз.

Также нужно решить по юридической части: на странице сейчас нет
блока с пометкой 18+ и реквизитами организатора — если по правилам
размещения он обязателен, скажите, добавим в подвал.
